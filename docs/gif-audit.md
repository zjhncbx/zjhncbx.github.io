# GIF 专项审计报告（gif-audit.md）

> 项目：`zjhncbx/zjhncbx.github.io`
> 阶段：P1
> 说明：本报告针对 `public/wp-content/uploads` 下全部 GIF（主要来自公众号/微信文章正文）做只读审计，
> 并按“是否可安全优化”分类。**未删除任何原始 GIF。**

## 一、总体

| 指标 | 数值 |
| --- | --- |
| GIF 文件总数 | 190 |
| 全部为动画（pages > 1） | 190（100%） |
| GIF 总体积 | 约 280 MB |
| 被渲染内容引用 | 188（绝大多数） |
| 磁盘缺失引用 | 0 |

> 关键：这 190 个 GIF 全部是**动态图**（如公众号文章中的示意图、海报动效），且几乎全部被文章正文引用，
> 属于必须保留动画效果的内容。**不得转换/删除为静态图。**

## 二、分类与处理

| 类别 | 数量 | 原体积 | 处理 | 结果 |
| --- | --- | --- | --- | --- |
| A 转动画 WebP（体积收益明显） | 121 | 274 MB | 生成 `.webp` 动画副本，`<picture>` 优先加载，原 `.gif` 保留 | 130 MB（**-53%**） |
| B 保留原 GIF（转换无收益/低价值） | 69 | 6 MB | 不处理（体积太小，转换无意义） | 保持 |
| 合计 | 190 | 280 MB | — | 130 MB（-150 MB） |

> 分类依据：
> - **A 类（转 WebP）：** 原 GIF ≥ 一定体积，且转换成动画 WebP 后明显更小（动画帧、时长完整保留）。脚本在
>   转换后对比体积，仅当新文件更小才采用；否则保留原 GIF（`kept-original`）。
> - **B 类（保留）：** 体积很小（合计仅 6 MB），转换收益忽略不计，直接保留原始 GIF，避免多余副本。

## 三、动画 WebP 兼容性

- 转换使用 `sharp` 的 `animated: true`，**完整保留帧数与播放时序**（已验证首屏/正文动画正常）。
- 渲染层通过 `<picture><source type="image/webp" srcset="...webp"><img src="...gif">` 提供：
  - 支持 WebP 的浏览器 → 加载更小的**动画 WebP**；
  - 不支持 WebP 的浏览器 → 回退到**原始 GIF**（历史 URL 完整保留）。
- 未转换 GIF 在两种浏览器下都加载原始 `.gif`，行为不变。

## 四、禁止事项遵守

- ❌ 未批量删除任何 GIF。
- ❌ 未把动态 GIF 转成静态图（动画全部保留）。
- ❌ 未猜测/编造任何 URL。
- ✅ 转换仅生成新副本，原 `.gif` 均保留。

## 五、示例（大 GIF 转换收益）

| 原图 | 原体积 | 动画 WebP | 收益 |
| --- | --- | --- | --- |
| `wxsync-2021-09-886bcf...html` | 9 MB | 2 MB | -78% |
| `wxsync-2021-07-e23318...` | 6 MB | 1 MB | -83% |
| `wxsync-2022-05-5b0ad0...`（首页近期资讯） | 4 MB | 2 MB | -50% |
| `wx_img_6a1429b48337d`（文章正文） | 4 MB | 2 MB | -51% |

## 六、结论

- GIF 是 P1 最大收益点：通过保留动画的 `GIF → 动画 WebP` 副本，节省约 **150 MB（53%）**。
- 因全部为动画内容且被引用，**未删除任何原图**，历史 URL 与动画效果完全保留。
- 后续 P2 可进一步评估：对极长动画转 `WebM/MP4`（需视频播放器，改动较大，风险高，另行评估）。

## 七、可复现

```bash
npm run images:gif    # 为被引用动态 GIF 生成动画 WebP 副本（保留原图）
```
